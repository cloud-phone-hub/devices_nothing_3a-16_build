## G. 属性上下文「文件」逐字节比对（真机 vs 云机，2026-09-27）

```
$ adb -s <dev> shell md5sum <path>        # 两侧同命令
文件                                     真机 md5/字节        云机 md5/字节        一致
plat_property_contexts                   54c2d331b0bb/112480  54c2d331b0bb/112480  ✓
system_ext_property_contexts             77b978cc47ed/37195   77b978cc47ed/37195   ✓
product_property_contexts                17a7f5c08e3a/920     17a7f5c08e3a/920     ✓
odm_property_contexts                    1cad6dd405a8/1057    1cad6dd405a8/1057    ✓
vendor_property_contexts                 e0a72697418d/63271   43e9b36e9d3c/63421   ✗
```

- 真机 `vendor_property_contexts` 与 gold 基包（`roms/gold_images_OS3.0.9.0…/vendor_a/etc/selinux/`）
  **md5 完全一致**（`e0a72697418dd10da712c9a726f5598a`）——对齐口径即"逐字节等于 gold"。
- 云机多出的 3 行（自身 keymint 修复注入，gold/真机均无）：

```
> # cdh note13-5G-15: remote keymint boot security_patch set
> ro.vendor.boot_security_patch u:object_r:vendor_security_patch_level_prop:s0 exact string
```

- 真机该属性**无映射**、运行时取值为空（`getprop ro.vendor.boot_security_patch` 空）；
  云机因远端 keymint HAL `std::stoi(getProperty(...))` 依赖非空值，保留此放行。
- **决策（用户确认，2026-09-27）：保留这 3 行**，作为唯一刻意偏差固证在案；
  区域文件清单不受影响（`vendor_security_patch_level_prop` 亦由 plat 的
  `ro.vendor.build.security_patch` exact 规则引用，744 集合不变）。
